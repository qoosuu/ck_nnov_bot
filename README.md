# Синий Кот: контент + бронирования

Готовое обновление существующего Python-бота. Один процесс: Telegram-бот, API мини-приложения и очередь уведомлений. Рабочий чат бронирований отделён от группы с фотографиями.

## Что умеет

- Приём фото, видео и кружочков в личке. Отправка в сохранённую тему пользователя в прежней группе; существующий `topics.sqlite3` совместим.
- Мини-приложение: горизонтальный календарь, переход к любой дате, 17 столов, несколько броней на стол, добавление, просмотр, изменение и удаление.
- Обязательные поля: ФИО, начало, число гостей, стол, дата смены. Необязательные: окончание, ссылка и комментарий. В ссылке допустимы `@username` и HTTP(S)-ссылки, в том числе на другие соцсети.
- Пересечения разрешены. Вместимость не проверяется. Начало/конец проверяются по часам смены. Никаких этапов подтверждения: запись сразу становится бронью.
- Удаление убирает бронь из календаря, сохраняя её в базе и журнале действий. Конфликт одновременного редактирования не затирает чужую работу.
- Владельцу 439275668 доступны открытия/уникальные сотрудники за сегодня, 7 и 30 календарных дней, управление доступом, время дайджеста, ручная сводка выбранной смены, очередь доставки и последние действия. «Разрешить» возвращает доступ участнику рабочего чата; не даёт режим владельца и не допускает посторонних.

## Смены и уведомления

Москва, `Europe/Moscow`. Вс–чт: 18:00–00:00; пт–сб: 18:00–03:00 следующего дня. Выбранная дата — день начала смены. Чтобы записать субботние 01:00, выберите пятницу и укажите 01:00. В 03:00 пятничная смена уже закончена.

По умолчанию в 16:00 приходит сводка: число броней и гостей, стол, время, ФИО, контакт и комментарий. Пустая сводка не отправляется. Длинная сводка разбивается на сообщения.

После времени сводки и до закрытия смены:
- новая бронь на эту смену → «Новая бронь сегодня», даже если в 16:00 ещё не было броней;
- изменение → уведомление с актуальными полями и прежним столом/временем;
- удаление → «Бронь отменена»;
- перенос на другую дату → сообщение об уходе из текущей смены, а при переносе в текущую — о новой брони.

Брони на будущие смены попадают в их будущие дайджесты, без немедленного уведомления. Гостям ничего не отправляется. Для прошлых закрытых смен автоматических уведомлений нет.

Ручной дайджест работает дополнительно к автоматическому, не отменяя его. Если вручную отправить сегодняшнюю сводку до обычного времени, дальнейшие изменения этой смены уже будут приходить в чат. Изменение времени не повторяет автоматически сводку, уже сформированную на эту смену. Новый час применяется к ещё не сформированным сводкам.

Очередь и отметки сводок хранятся в SQLite. После простоя бот догоняет сводку текущей незакрытой смены. Повторы сетевых ошибок идут с задержкой, сообщения — с учётом ограничения частоты Telegram. Обычно новая бронь поступает через несколько секунд; при очереди/сбое позже. Редкий обрыв после принятия сообщения Telegram, но до подтверждения серверу, может дать дубль при повторной доставке: Telegram не предоставляет ключ идемпотентности для sendMessage.

## Обновление через Git на текущем сервере

Репозиторий: `https://github.com/qoosuu/ck_nnov_bot.git`, ветка `main`.
Рабочая папка службы: `/opt/ck_nnov_bot/ck_nnov_bot`.

Перед первым обновлением проверьте Python **внутри рабочей папки службы**, сохраните резервную копию папки при остановленной службе, затем выполните:

```sh
cd /opt/ck_nnov_bot/ck_nnov_bot
git pull --ff-only origin main
./venv/bin/python -m pip install --no-cache-dir -r requirements.txt
```

Не используйте `git reset --hard` при конфликте: сначала разберите локальные изменения. `.env`, базы SQLite и `venv` исключены из Git.

HTTPS на IP уже настроен отдельно в `/opt/ck-nnov-https`. Создайте `/opt/ck-nnov-https/booking.env`:

```dotenv
MINI_APP_URL=https://185.229.65.77
WEB_HOST=127.0.0.1
WEB_PORT=8080
```

В `/etc/systemd/system/ck-nnov-bot.service.d/booking.conf` добавьте:

```ini
[Service]
EnvironmentFile=/opt/ck-nnov-https/booking.env
```

Этот дополнительный файл дополняет прежние настройки токена и группы. Существующий файл службы заменять не нужно. Затем:

```sh
systemctl daemon-reload
systemctl start ck-nnov-bot
systemctl status ck-nnov-bot --no-pager -l
```

В рабочем чате владелец отправляет `/register`, в личке каждый сотрудник — `/iamworker`.

## Установка на существующий сервер

Нужны Python 3.10+ (проверено на 3.12), существующий токен бота, адрес с публичным HTTPS (домен или IP с доверенным сертификатом) и установленными системными часовыми поясами. Сборка JavaScript не нужна.

1. Остановите существующую службу и сделайте резервную копию её папки:
   ```sh
   sudo systemctl stop ck-nnov-bot
   sudo cp -a /opt/ck_nnov_bot/ck_nnov_bot /opt/ck_nnov_bot/ck_nnov_bot.backup-$(date +%Y%m%d-%H%M%S)
   ```
2. В `/opt/ck_nnov_bot/ck_nnov_bot/` скопируйте из обновления `bot.py`, `media.py`, `topics.py`, `requirements.txt` и всю папку `booking/`. Сохраните прежние `.env`, `venv/` и `topics.sqlite3`. Если обновляете повторно, сохраните также `bookings.sqlite3` и его сопутствующие файлы. Не запускайте старую и новую версии одновременно.
3. Установите зависимости:
   ```sh
   /opt/ck_nnov_bot/ck_nnov_bot/venv/bin/pip install -r /opt/ck_nnov_bot/ck_nnov_bot/requirements.txt
   ```
4. В существующую `.env` добавьте:
   ```dotenv
   MINI_APP_URL=https://185.229.65.77
   WEB_HOST=127.0.0.1
   WEB_PORT=8080
   ```
   `BOT_TOKEN` и `GROUP_CHAT_ID` оставьте прежними. `GROUP_CHAT_ID` — группа для контента, не рабочий чат. При конфликте порта измените его и в настройке прокси.
5. Настройте публичный HTTPS-прокси на `127.0.0.1:8080`. В `deploy/Caddyfile.example` готовый блок для Caddy. Потребуются DNS-запись домена на IP сервера и доступные порты 80/443. Добавляйте блок к имеющейся конфигурации, не заменяя чужие сайты. Если на сервере уже есть Nginx, используйте его для той же прокси-схемы. Сам Python-сервис наружу открывать не нужно.
6. Старая служба подходит: путь запуска остался `bot.py`. Образец обновлённой службы находится в `deploy/`; применять его необязательно. Если меняете файл службы, выполните `sudo systemctl daemon-reload`.
7. Запустите и проверьте:
   ```sh
   sudo systemctl start ck-nnov-bot
   sudo systemctl status ck-nnov-bot
   sudo journalctl -u ck-nnov-bot -n 50 --no-pager
   ```
   Открытие HTTPS-адреса обычным браузером покажет предложение войти через Telegram — это ожидаемо.

Без `MINI_APP_URL` пересылка контента работает, но кнопка приложения не выдаётся. Для полноценного запуска бронирований HTTPS-адрес обязателен. Для текущего сервера используется `https://185.229.65.77`; покупка домена не нужна.

## Подключение рабочего чата

1. Добавьте того же бота в отдельный чат сотрудников **без топиков**, назначьте администратором с правом отправки сообщений. Администраторские права нужны для надёжной проверки участия сотрудников.
2. Со своего аккаунта **439275668** напишите в нём `/register` или `/register@имя_бота`. Пишите от личного аккаунта, не анонимно от имени группы. Другие люди не могут зарегистрировать чат.
3. Бот сохранит этот чат как источник доступа и адрес сводок. Повторный `/register` в другом чате заменит привязку; брони сохранятся, неотправленная очередь прежнего чата будет очищена.
4. Каждый сотрудник открывает личный чат с ботом и нажимает `/start` (либо `/bookings`). Если сотрудник уже пользовался ботом, он может отправить **`/iamworker` в личном чате с ботом**: команда заново проверит участие в зарегистрированном рабочем чате и обновит кнопку меню. Её можно повторять после вступления в чат или восстановления доступа; ручное отключение владельцем она не отменяет. В меню появляется «Бронирования». Владельцу там же доступен раздел «Управление».
5. Гостям кнопка приложения не выдаётся. Проверка подписанных данных Telegram и текущего участия в рабочем чате выполняется при каждом запросе к данным. Отключённый сотрудник не получает данные, даже если сохранил ссылку или кнопку. Кнопки обновляются при изменении членства, команде и периодически; интерфейс Telegram может показать старую кнопку до обновления.

Не включайте глобальную Main Mini App / публичную кнопку приложения в профиле через BotFather: в этой версии используются индивидуальные кнопки меню. Бот не выгружает весь список участников: список в управлении пополняется по обращениям и событиям участия. Отдельная ручная загрузка 11 сотрудников не требуется.

## Проверка после установки

- Отправить фото, видео и кружочек: они должны остаться в прежней пользовательской теме.
- Владелец выполняет `/register`; сотрудник и посторонний запускают `/start`: кнопку получает сотрудник.
- Создать две пересекающиеся брони стола №17, изменить число гостей, открыть ссылку, удалить одну запись.
- Для пятничной смены сохранить 01:00: это субботняя ночь внутри пятницы.
- В «Управлении» вручную отправить сводку. После времени сводки проверить создание, изменение и удаление текущей брони.
- Отключить тестового сотрудника, проверить запрет данных, вернуть доступ.
- Перезапустить службу и проверить сохранность тем, броней, настроек и отсутствие повторной автоматической сводки.

## Файлы и данные

- `bot.py` — общий запуск.
- `media.py`, `topics.py` — прежняя функция пересылки.
- `booking/domain.py` — время смен и проверка полей.
- `booking/store.py`, `booking/service.py` — база, изменения, очередь и дайджесты.
- `booking/access.py`, `booking/telegram.py` — права, меню, `/register`.
- `booking/web.py`, `booking/static/` — API и интерфейс.
- `topics.sqlite3` — соответствие пользователей и тем для фотографий.
- `bookings.sqlite3` — брони, доступы, настройки, история, статистика и очередь. Создаётся автоматически рядом с `bot.py`; путь меняется через `BOOKINGS_DB_PATH`.

Запускайте один экземпляр службы. Базы должны храниться на постоянном диске. Для резервной копии используйте SQLite backup или останавливайте службу и копируйте папку целиком. Токен не попадает в браузер; реальные базы и `.env` в этот архив не включены.

## Локальные проверки

```sh
python -m unittest discover -s tests -v
```

`tests/ui_server.py` — отдельный локальный стенд на 127.0.0.1:8765 с вымышленными бронями и тестовым Telegram-клиентом. Он использует временную базу, не отправляет сообщений и не запускается основным ботом. `tests/browser.cjs` проверяет интерфейс через Playwright. Запустите стенд, затем `node tests/browser.cjs` в окружении с Playwright/Chromium; для другого установленного Chromium-браузера можно задать `BROWSER_EXECUTABLE`.

Проверка с настоящим Telegram и установка на ваш сервер выполняются отдельно: в этой задаче токен и доступ к серверу не предоставлялись.

Документация: [проверка данных Mini App](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [проверка участника](https://core.telegram.org/bots/api#getchatmember), [индивидуальное меню](https://core.telegram.org/bots/api#setchatmenubutton), [HTTPS-прокси Caddy](https://caddyserver.com/docs/quick-starts/reverse-proxy).
